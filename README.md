# Бонусная система кофейни — кэшбэк бонусами

Сайт целиком живёт на **GitHub Pages**, а база данных и расчёты бонусов — в бесплатном облаке **Supabase**. Свой сервер и включённый компьютер не нужны.

- **Клиенты:** открывают сайт или приложение, регистрируются (имя, логин, пароль), показывают QR на кассе. Вход через Telegram — по желанию.
- **Бариста:** `…/barista/` — сканер QR, ввод чека, списание бонусов, отмена.
- **Владелец:** `…/admin/` — точки, сотрудники, клиенты, статистика, правила.
- **Android-приложение:** оболочка над тем же сайтом (папка `android/`).

**Правила (меняются в админке):** с любой покупки начисляется **5%** бонусами, **1 бонус = 1 ₽**, бонусами можно оплатить не больше **20% чека**. Бонусы начисляются с суммы, оплаченной деньгами (за вычетом списанных бонусов). Баланс единый для всей сети.

Пример: чек 500 ₽, у клиента 120 бонусов. Списать можно до 100. Клиент платит 400 ₽ и получает 5% от 400 = 20 бонусов. Баланс: 120 − 100 + 20 = 40.

## Как это устроено

```
телефон/браузер ──► GitHub Pages (docs/: страницы, QR, интерфейс)
        │
        └──────────► Supabase (Postgres): таблицы закрыты, снаружи доступны только
                     функции из supabase/migrations/, каждая проверяет токен роли
```

- Таблицы лежат в схеме `app_private`, недоступной из интернета. Любое действие идёт через функции, которые сами проверяют, кто спрашивает (клиент, бариста или админ) и что ему можно.
- Ключ в `docs/assets/config.js` — публичный (anon/publishable). Он не даёт доступа к таблицам, поэтому его безопасно хранить в репозитории. **Ключ `service_role` сюда вставлять нельзя.**
- QR клиента живёт ровно минуту (кольцо-таймер плавно убывает), следующий код подгружается заранее и подменяется без пауз; код подписан, скриншот не поможет.
- Пароли клиентов хранятся только в виде хэша (bcrypt). При регистрации клиент получает **код восстановления** (`XXXX-XXXX-XXXX-XXXX`, хранится как хэш, после использования меняется на новый). Забыл пароль — «Забыли пароль?» на входе. Новый код можно выпустить в настройках. Если потеряны и пароль, и код — администратор: «Клиенты» → карточка → «Сбросить пароль».
- Все операции пишутся в журнал: кто, когда, на какой точке. Попытки входа ограничены (10 неудач за 5 минут).

## Запуск с нуля (один раз, ~10 минут)

### 1. Создайте проект Supabase
1. Зарегистрируйтесь на https://supabase.com и нажмите **New project** (тариф Free). Запомните пароль базы, он нам не понадобится.
2. Дождитесь, пока проект создастся.

### 2. Примените схему
1. В проекте откройте **SQL Editor → New query**.
2. Вставьте всё содержимое файла `supabase/schema.sql` (собран из миграций) и нажмите **Run**. Должно появиться `Success`.
3. **Database → Extensions** → включите `pg_net` (нужен для Telegram и push). Если уже включено — ничего делать не нужно.

**Обновление уже работающей базы:** выполните в SQL Editor только новые файлы из `supabase/migrations/` (по номеру). Применённые версии записаны в `app_private.schema_migrations`. Новая миграция = новый файл `NNNN_название.sql`, затем `python supabase/build_schema.py` пересобирает `schema.sql`.

### 3. Подключите сайт к проекту
1. **Project Settings → API**: скопируйте **Project URL** и публичный ключ (**anon public** или **publishable**).
2. Впишите их в `docs/assets/config.js`:
   ```js
   window.APP_CONFIG = {
     SUPABASE_URL: 'https://xxxx.supabase.co',
     SUPABASE_KEY: 'eyJ...',   // anon/publishable, не service_role!
   };
   ```
3. Закоммитьте и запушьте: Pages обновится за минуту.

### 4. Включите GitHub Pages
Репозиторий → **Settings → Pages** → Source: **Deploy from a branch**, ветка `main`, папка `/docs`.

Сайт откроется по адресу `https://<аккаунт>.github.io/<репозиторий>/`.

### 5. Подключите Telegram (когда будете готовы)
1. В @BotFather: `/newbot` → получите **токен** и имя бота. Затем `/setdomain` → укажите `<аккаунт>.github.io`.
2. В Supabase → SQL Editor выполните (подставьте свои значения):
   ```sql
   update app_private.config set value = '123456:ВАШ_ТОКЕН'   where key = 'bot_token';
   update app_private.config set value = 'ИмяВашегоБота'      where key = 'bot_username';
   update app_private.config set value = 'Название кофейни'    where key = 'shop_name';
   ```
3. Кнопка Telegram появится на странице входа рядом с регистрацией по логину и паролю.

### 6. Push-уведомления клиентам (по желанию)
1. Supabase → **Edge Functions → Deploy a new function** → имя `send-push`, вставьте код из `supabase/functions/send-push/index.ts`, **отключите «Verify JWT»**, Deploy.
2. Админка → «Правила» → «Push-уведомления клиентам» → **Подключить**. Ключи VAPID создаются автоматически, вводить секреты не нужно.
3. Клиенты включают уведомления в настройках сайта. Ограничения: в Android-приложении (WebView) push не работает — только в браузере; на телефонах без сервисов Google (например Huawei) доставка зависит от браузера.

## Возможности для владельца (миграция 0003)

- **Срок жизни бонусов** — «Правила» → «Через сколько дней без покупок бонусы сгорают». 0 — не сгорают. Отсчёт идёт от последней покупки; клиент видит дату сгорания на карте и получает сообщение, когда бонусы сгорели.
- **Бонус за регистрацию** — «Правила» → «Сколько бонусов дарить за регистрацию». Бонус тоже сгорает по общему сроку.
- **Отчёты** — вкладка «Отчёты»: выручка, средний чек, новые и вернувшиеся покупатели, часы пик, точки, лучшие клиенты; выгрузка покупок в CSV (открывается в Excel).
- **Рассылки** — вкладка «Рассылки»: всем, у кого есть бонусы, или не покупавшим 30+ дней. Сообщение попадает во «Сообщения» клиента, в push и в Telegram. Раз в полминуты не чаще.
- **Касса без интернета** — если связи нет, QR всё равно сканируется: покупка запоминается на устройстве бариста (только начисление, списать бонусы без связи нельзя) и отправляется сама, когда интернет вернётся. Сервер проверяет QR по времени сканирования (до 3 суток назад) и не даёт провести покупку дважды; непринятые покупки остаются в карточке «Очередь» для ручной проверки. Часы телефона кассы должны идти правильно. Ручной ввод номера карты и кода без интернета не работает.

## Обновление приложения

Страница в приложении сверяет свою версию с `docs/app-version.json` и предлагает «Обновить»: приложение скачивает APK из последнего релиза и открывает установщик Android (подтвердить установку нужно вручную; при первом разе разрешите установку из этого приложения). Выпуск новой версии:
1. В `android/build_apk.py` увеличьте `VERSION_CODE`/`VERSION_NAME`, в `MainActivity.java` — `APP_VERSION`.
2. Обновите `versionCode`/`versionName` в `docs/app-version.json`.
3. `python android/build_apk.py --url https://<аккаунт>.github.io/<репозиторий>/`, затем `gh release upload v1.0 Kofe-karta.apk --clobber`.

Приложение само опрашивает базу (примерно раз в 15 минут) и показывает уведомления о бонусах и акциях без сервисов Google. Android и оболочки телефонов (Huawei, Xiaomi) могут откладывать фоновые задачи, поэтому сообщения приходят с задержкой; для мгновенных уведомлений используйте сайт в браузере (Web Push).

## Android-приложение

Папка `android/`, готовый файл — в [Releases](../../releases). Скачивание: страница `…/download/`.
Приложение открывает сайт на весь экран и разрешает камеру для сканера. Сборка (нужны Android SDK и JDK, Gradle не нужен):
```
cd android
python build_apk.py --url https://<аккаунт>.github.io/<репозиторий>/
```
Файл подписан тестовым ключом, поэтому Android предупредит о «неизвестном приложении». Для Google Play нужен свой ключ и формат AAB.

## Проверка и разработка

- `supabase/test_schema.py` — 200+ проверок логики (начисление, лимит 20%, отмена, права, вход, восстановление, push, обновление 0001→0002) на Postgres: локально в Docker или через `PGHOST/PGUSER/PGPASSWORD`.
- `tools/check_site.py` — ссылки, синтаксис скриптов, поиск секретов.
- `.github/workflows/ci.yml` — те же проверки и сборка APK автоматически при каждом push.
- `supabase/rest_shim.py` — локальный стенд: имитация Supabase REST и раздача `docs/` по адресу `http://localhost:8090/coffee-bonus/`.

Контейнер для тестов: `docker run -d --name coffee-pg-test -e POSTGRES_PASSWORD=test -p 127.0.0.1:54329:5432 postgres:16-alpine`, затем создать роли `anon`, `authenticated` и заглушку схемы `net` (см. начало `test_schema.py`).

## Структура

| Путь | Что это |
|---|---|
| `docs/` | весь сайт для GitHub Pages: клиент (`index.html`), `barista/`, `admin/`, `auth/` (приёмник входа Telegram), `download/` |
| `docs/assets/config.js` | адрес и публичный ключ Supabase |
| `supabase/migrations/` | миграции базы (источник истины); `schema.sql` — их сборка |
| `supabase/functions/send-push/` | Edge Function отправки push |
| `tools/`, `.github/` | проверки и CI |
| `android/` | исходники приложения и скрипт сборки APK |
